# PLAY-16 — ذاكرة الأحداث التي شاهدها كارلوس بنفسه

**المجال:** القرية التجريبية فقط. لا تعديل على عالم القصة الأصلية أو `main`.

## ما يضيفه التنفيذ

في وضع `--npc-survival-demo` يمكن لكارلوس رؤية شخصية تأكل أثناء `wait`.
تُسجّل عندئذٍ **مشاهدة محلية صادقة** في سجل الأحداث نفسه،
قبل حدث `NPCFoodConsumed` الفعلي مباشرة وفي أمر انتظار واحد،
فقط عندما يكون كلاهما في المكان نفسه وغير مسافرين.

يُظهر `remember` الحقل الاختياري `witnessed_events`، ويعيد `handoff`
نفس الذكريات عبر `player_memory`. يسرد كل سجل
`actor_id / activity / location_id / at` فقط؛ ولا يكشف كمية الطعام،
مخزون NPC، سبب تناوله الطعام أو مستوى الجوع.

يُقبل الحدث في ذاكرة اللاعب **فقط** إذا:
1. كان `PlayerObserved` صادرًا باسمه، من بوابة الانتظار،
   بمصدر `player witnessed a nearby NPC eating`؛
2. تبعه مباشرة `NPCFoodConsumed` داخل أمر `player-wait:` ذاته؛
3. اتفقت هوية الشخصية ومكان الوجبة وتوقيتها مع المشاهدة المحفوظة.

لا تُستنبط معرفة عن الوجبات البعيدة من دفتر `consumptions` الكامل.
أي استدعاء مباشر مستقل لخدمة أكل NPC لا يصنع ذكريات للاعب تلقائيًا.
القراءة لا تغيّر العالم ولا تضاعف الأحداث؛ أحدث 20 ذكرى فقط تُعرض.

## تجربة يدوية

من داخل `simulation`:

```powershell
$env:PYTHONPATH = "src"
python scenarios/test_village/play_living_village.py --npc-survival-demo
```

ثم:

```text
remember
wait 1
remember
handoff
quit
```

المتوقع: ظهور وجبة باسم في الذاكرة فقط؛ نورا التي تأكل بعيدًا لا تظهر.
يمكن استئناف ملف التجربة بالطريقة المعتادة مع الخيار نفسه.

## حدود الثقة والتوافق

- لا توجد واجهة HTTP أو هوية مستخدم شبكية معتمدة؛ `PlayerGateway`
  و`LivingWorldEngine` قدرات محلية موثوقة، وليستا مصادقة شبكة.
- يعتمد الاسترجاع على أحداث تم التحقق منها عبر `store.verify`،
  ولا يمنح النموذج اللغوي حق تعديلها.
- لا تغيير في Schema 34 أو Rules 46، ولا ترحيل صامت.
- الوضع العادي دون NPC survival لا يضيف مشاهدات أكل غير موجودة.
- PLAY-14g و03-A7c و03-A والاعتماد الإنتاجي P0 والمراجعة الخارجية
  ما زالت مفتوحة.

**حالة التنفيذ:** الشيفرة واختبارات الانحدار موجودة على الفرع
`simulation-engine-phase-play-16-witnessed-memory`.
**إغلاق PLAY-16 النهائي يعتمد على نجاح CI للنسخة النهائية**
على Python 3.10 و3.13؛ لا يُعتبر مجرد رفع الشيفرة إغلاقًا.
