# PLAY-07 — هدية حقيقية من كارلوس إلى شخصية في القرية

**نسخة تجريبية محلية معزولة.** أصبح بإمكان كارلوس تسليم الخبز أو مورد آخر يملكه بالفعل إلى شخصية غير لاعبة في موقعه. نقل الملكية يُسجَّل في SQLite ويُعاد تطبيقه بصورة حتمية؛ الهدية لا تُنشئ خبزًا أو نقودًا.

## التجربة في PowerShell

افتح مجلد simulation:

~~~powershell
$env:PYTHONPATH = "src"
python scenarios/test_village/play_living_village.py
~~~

نفّذ:

~~~text
supplies
buy salma-bread 2 2
supplies
give salma bread 1
supplies
handoff
quit
~~~

بعد الشراء: يملك كارلوس رغيفين و6 قطع نحاسية، وتملك سلمى رغيفًا و4 قطع نحاسية. بعد إعطاء سلمى رغيفًا، يصبح رصيد كارلوس رغيفًا واحدًا ورصيد سلمى رغيفين؛ يبقى إجمالي الخبز ثلاثة، وإجمالي النحاس عشرة. **المشتريات المسجلة تبقى مشتريات**؛ الهدية لا تعكس الصفقة ولا تعيد النقود ولا تعيد نشر العرض.

## سلوك الشخصيات وقيود العملية

- الأمر: `give <npc-id> <resource> <quantity>`، ضمن حد أقصى 1000 وحدة في المحاولة الواحدة.
- يجب أن يكون كارلوس والشخصية قريبين وغير مسافرين، وأن تكون الشخصية متاحة جسديًا وليست في عمل يمنع استلامها.
- ترفض الشخصية الهدية عندما تكون استجابتها المحددة مسبقًا لعرض المساعدة «عدم ثقة»، وفق علاقتها الحالية بكارلوس. لا تُضاف نقاط ثقة أو امتنان تلقائيًا.
- لا تُقبل موارد مجهولة أو أرصدة غير مهيأة أو أرقام سالبة أو موارد النظام الداخلية أو طلب يجعل المخزون سالبًا أو متجاوزًا لحدوده. الفشل لا يسحب أي شيء.
- التسليم لا يشبع الجوع، ولا يعالج الإصابة، ولا يُضيف خبرة أو عناصر إلى حقيبة RPG؛ تلك كلها أنظمة منفصلة لها قواعد لم تُعتمد لهذا الأمر.
- سجل مصدر التفويض لعملية الهدية مستقل عن تفويض السوق والتواصل الاجتماعي، ويُراجَع عند إعادة تشغيل الأحداث. معرّف الطلب يمنع تنفيذ الهدية مرتين بعد استئناف الحفظ.
- التشغيل التجريبي لا يمنح واجهة HTTP أو أي مستخدم بعيد حق إعطاء الهدايا؛ `PlayerGateway` خدمة محلية موثوقة فقط.
