# PLAY-17 — ذاكرة كارلوس للأنشطة المشاهدة

**المجال:** تجربة القرية المحلية فقط، دون تعديل `main` أو قصة كارلوس.

## التحليل المعتمد قبل التنفيذ

كان `scene` يعرض نشاط NPC الحالي (العمل، الراحة، البحث عن طعام،
الإنتاج) دون حفظه. وكان `look` يسجّل الموقع والحضور فقط.
هدف PLAY-17 هو ربط **المشاهدة الاختيارية الحقيقية** بذاكرة لاحقة،
دون أن تتحول معلومات محرك NPC الخاصة إلى معرفة للراوي.

## آلية التنفيذ

- يُعاد استعمال منطق المشاهدة الفيزيائي نفسه بين `scene` ومُحقّق
  `PlayerObserved`؛ لا يوجد مساران متناقضان لتحديد ما يُرى.
- `scene` و`handoff` و`remember` لا يُنشئون أحداثًا؛ لا تكتب
  ذاكرة جديدة إلا عند أمر `look` صريح، وفي المكان الذي يوجد فيه
  كارلوس فعلًا.
- إذا كان أحد NPC يعمل/يرتاح/يبحث عن طعام/ينتج **في تلك اللحظة**
  يضيف `PlayerObserved` قائمة `activities` اختيارية إلى الحدث
  المتحقق منه. عند عدم وجود نشاط ظاهر، يحتفظ الحدث بهيئته القديمة.
- يُراجع المحرك القائمة بالكامل مقابل حالة العالم والتوقيت والحضور
  لحظة الحدث. يُرفض تزوير نشاط أو NPC بعيد أو لاعب مسافر أو إضافة
  بيانات خاصة أو حفظ مشاهدة داخل أمر غير `player-observe:`.
- `remember` و`handoff.player_memory.witnessed_events` يعيدان
  `actor_id` و`activity` و`location_id` و`at` فقط.
  لا تُسرب أهداف الشخصيات أو الجروح أو الطعام أو الوصفات أو المواعيد.
- يستمر استرجاع وجبات PLAY-16 من اقتران حدث مشاهدة بأكل فعلي.
  يحتفظ العرض بأحدث 20 حدثًا مشاهدًا إجمالًا بالترتيب؛ سجل
  الأحداث الكامل لا يُحذف ولا يُختزل.
- لا تُعاد كتابة مشاهدة سابقة من حالة عالم لاحقة. حتى إذا انتهى
  النشاط، تظل مشاهدة الوقت الأصلي كما أُثبتت.

## طريقة التجربة

من مجلد `simulation`، استخدم:

```powershell
$env:PYTHONPATH = "src"
python scenarios/test_village/play_living_village.py
```

ثم:

```text
wait 1
scene
remember
look
remember
handoff
```

`scene` وحده لا يصنع ذاكرة. بعد `look` تظهر فقط الأنشطة
المستمرة فعليًا قرب كارلوس. شخصية تعمل بعيدًا لا تظهر.
