# PLAY-03 — احفظ قرية كارلوس التجريبية واستأنفها على Windows

هذا مثال **محلي وتجريبي فقط**: كارلوس وسبع شخصيات مستقلة تتصرف عند تقدم الوقت، مع ملف SQLite يمكن إغلاقه ثم إعادة فتحه. **ليس حفظ قصة كارلوس الأصلية أو موافقة على تشغيل إنتاجي**؛ مراجعة P0 الخارجية ما تزال مفتوحة.

## 1. أنشئ تجربة جديدة

من داخل مجلد `simulation` عبر PowerShell، وداخل نسخة مشروع Git محلية مطابقة للفرع الحالي:

```powershell
$env:PYTHONPATH = "src"
New-Item -ItemType Directory -Path living-backups
$sha = git rev-parse HEAD
python scenarios/test_village/play_living_resumable.py --db living-test.sqlite --backups living-backups --new --code-commit $sha --disposable-test
```

ملاحظات: يُشترط أن يكون **ملف** `living-test.sqlite` غير موجود وأن يكون **مجلد** `living-backups` موجودًا وفارغًا من نقاط `living-test-rev-*`. استخدم مجلدًا خاصًا لكل عالم جديد؛ لا تُعد استخدام مجلد النسخ الاحتياطية لعالم آخر. قيمة `$sha` معرّف Commit حقيقي كامل من نسختك، ولا يجوز تغييره عشوائيًا.

جرّب:

```text
scene
look
talk basim greeting Hello
wait 180
handoff
move square-woods
wait 49
scene
quit
```

المحاكاة تسجل أفعال الشخصيات ووقت رحلتك، بينما تختار أنت أفعال كارلوس. `scene` و`handoff` و`remember` و`status` **للقراءة فقط**. `look` يُسجل مشاهدة فعلية. تُحفظ نقاط تحقق مستقلة بعد الأوامر المؤثرة، وتُترك قاعدة البيانات بعد الإغلاق.

## 2. استأنف القرية نفسها

ضمن **نفس إصدار الكود المطابق لحفظك**، استخدم نفس قيمة `$sha` ونفس الملف والمجلد:

```powershell
python scenarios/test_village/play_living_resumable.py --db living-test.sqlite --backups living-backups --resume --code-commit $sha --disposable-test
```

ثم جرّب `wait 1` لإكمال الرحلة ذات الخمسين ثانية: يبقى كارلوس في الطريق لحين وقت الوصول. قبل `wait` لا يتقدم الزمن تلقائيًا أثناء إغلاق البرنامج، ولا تتحرك الشخصيات بسبب الوقت الحقيقي.

إذا تغيّر إصدار القواعد أو انقطعت نقطة التحقق اللازمة أو اختلفت بصمة النسخة/الحالة، يرفض البرنامج الاستئناف بدل إعادة إنشاء العالم أو تجاهل الاختلاف. هذه حماية تجريبية؛ ليست خطة ترحيل بيانات أو ضمان استعادة إنتاجية.

## 3. معرّفات الطلبات وعدم تكرار الفعل

يمكنك كتابة `id first-look look` أو `id first-trip move square-woods`. إذا أعدت إرسال **نفس المعرّف لنوع الأمر نفسه** بعد الإغلاق، يرفض المحرك تنفيذه مرتين. دون بادئة `id` يختار البرنامج معرّفًا مرتبطًا بالمراجعة الحالية للعالم.

يُنصح باستخدام `id` للأوامر المهمة عند تجربة إعادة الإرسال؛ لا تُعد تشغيل حدث بإنشاء معرّف جديد إلا إذا كنت ترغب فعلًا بإجراء جديد.

## 4. حدود الأمان والمعرفة

- مصدر الحقيقة هو المحرك وسجل أحداث SQLite؛ لا ينفذ ChatGPT أوامر على العالم من مخرجات `handoff`.
- تُعرض فقط المعلومات المتاحة لكارلوس، وليس إصابة نورا السرية أو نوايا هدى البعيدة.
- كل الموارد والتفاعلات والرحلات تحتاج أسبابًا معتمدة؛ لا يُنشئ العرض مالًا أو غذاءً.
- `P0_PRODUCTION_NOT_APPROVED`: ممنوع اعتبار ملفات التجربة أرشيفًا آمنًا طويل المدى قبل التحقق على جهازك من مسارات النسخ/الاستعادة والنسخة الفعلية.
- لا تُشغّل واجهة شبكة عامة أو تسمح لمستخدم غير موثوق بإدارة هذا المحرك. العالم التجريبي غير متصل بالإنترنت ولا يستلزم API.

## 5. أدلة قبول PLAY-03

`simulation/tests/test_play_living_resumable_batch_03.py`: اختبار فتح/إغلاق في عمليتي Python منفصلتين، مستقلية سبع شخصيات، استمرار الجداول بعد الاستئناف، السفر الذي لا يتجاوز الزمن، منع تكرار معرّف، خصوصية `handoff`، SQLite/replay، ورفض الحفظ/النسخ المفقودة أو القديمة أو المتعارضة. لا تُعتمد الدفعة إلا بعد نجاح GitHub Actions على SHA النهائي في Python 3.10 و3.13.
